# Позитив ВТ: продающий лендинг агентства недвижимости

Лендинг московского агентства недвижимости «Позитив ВТ» (ООО «Агентство «Позитив ВТ», ИНН 7707723617). Next.js 16 (App Router) + Tailwind v4 + Motion. Все цифры и объекты на странице реальные: подтягиваются с ЦИАН и Домклик.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

Продакшен:

```bash
npm run build
npm start
```

## Данные: откуда и как обновлять

Источник правды: JSON-файлы в `data/`, которые сайт читает **с диска в рантайме** (lib/data.ts). Ночной синк на сервере просто перезаписывает их, и страница сразу отдаёт свежие данные: без пересборки, рестарта и коммитов в git.

- `data/listings.json` — объявления агентства (ЦИАН + Домклик)
- `data/agency.json` — статистика, команда и отзывы (Домклик)

Обновление одним скриптом:

```bash
npm run sync
```

Что делает `scripts/sync-listings.mjs`:

1. **Домклик** — обычный fetch: статистика агентства (20 сделок/12 мес, рейтинг 5.0), 7 риелторов с аватарами, 7 отзывов + объявления через открытый API `api.domclick.ru/pts/agencies/v1/offers`.
2. **ЦИАН, состав объявлений** — если в env задан `CIAN_API_KEY`
   (официальный [ЦИАН API](https://public-api.cian.ru), ключ выдаётся
   агентству в ЛК бесплатно), список опубликованных и снятых объявлений
   берётся из API — без браузера и антибот-рисков. Проверка ключа:
   `npm run sync:test-api` (ключ кладётся в `.env.local`).
3. **ЦИАН, контент** — цены, адреса и фото в API не отдаются, поэтому
   страница компании [cian.ru/company/211681](https://www.cian.ru/company/211681)
   открывается через `playwright-core` + установленный Google Chrome
   (headless); новые объявления, которых нет на странице, добираются с их
   собственных страниц. Без ключа API этот же парсинг определяет и состав
   (как раньше, с проверкой снятых по прямым ссылкам).
4. Фото скачиваются в `public/listings/<id>/`, аватары в `public/team/` (хотлинки не используются).
5. Рукописные поля (`title`, `highlight`, `address`) существующих объектов сохраняются при обновлении; снятые с публикации объявления удаляются, новые добавляются.

Важно (режим без ключа API): страница компании на ЦИАН показывает не все объявления разом (ротация карточек). Поэтому объявления, пропавшие из профиля, скрипт проверяет по прямым ссылкам и удаляет только те, где ЦИАН отвечает «снято с публикации». С ключом API эта механика не нужна: снятые определяются по статусу. Фото снятых объявлений в обоих режимах подчищаются из `public/listings/`.

### Автообновление каждый день в 00:00

**Прод (VPS)**: systemd-таймер из деплой-кита ([deploy/positiv-vt-sync.timer](deploy/positiv-vt-sync.timer)) запускает синк на сервере в 00:00 МСК. Данные обновляются на диске in place — пересборка, рестарт и git не нужны.

**Демо (Vercel)**: собирается из main при пуше (или `npx vercel --prod`).
Данные демо — те, что закоммичены в `data/`; освежить их можно локальным
`npm run sync` и пушем. Прежний GitHub Action с ночным коммитом данных
удалён: рабочая модель — синк на VPS, без пересборок и коммитов.

Если ЦИАН недоступен, прежние данные остаются как есть.

Сбои источников не молчат: скрипт шлёт алерт теми же каналами, что и
уведомления о заявках (email + MAX + Telegram, какие настроены в env).
Проверить каналы: `node scripts/sync-listings.mjs --test-notify`.

## Заявки: журнал + email + MAX (+ Telegram как опция)

`POST /api/lead` принимает `{ name, phone, task, consent, object?, comment? }`.
Пайплайн ([lib/leads.ts](lib/leads.ts)):

1. **Журнал на сервере** (обязательный шаг): заявка пишется в JSONL
   `data/leads/leads-ГГГГ-ММ.jsonl` (путь настраивается `LEADS_DIR`) вместе с
   фактом согласия (дата, время, IP). Это требование 152-ФЗ о первичной записи
   ПДн в РФ и страховка от потери лидов. Каталог в git не попадает.
2. **Уведомления** (каждый канал включается своими env, все с ретраями):
   - email через SMTP (`SMTP_*`, `LEAD_EMAIL_TO`) — основной канал для РФ;
   - бот в MAX (`MAX_BOT_TOKEN`, `MAX_CHAT_ID`, API platform-api2.max.ru) —
     вторичный; бот создаётся через @MasterBot в MAX;
   - Telegram (`TELEGRAM_*`) — опция для не-РФ окружений (с VPS в РФ
     api.telegram.org блокируется, см. research/05).
3. Валидация, honeypot, rate-limit 5/мин c IP; без отметки согласия заявка
   отклоняется.

Все переменные описаны в `.env.example`.

## Карта в подвале

Компонент [components/OfficeMap.tsx](components/OfficeMap.tsx) выбирает вариант по `YANDEX_MAPS_API_KEY`:

- **ключ задан** — карта на JS API Яндекс Карт 3.0 ([components/map/](components/map/)): схема перекрашена под палитру сайта (`mapStyle.ts`), вместо метки плашка агентства с телефонами и маршрутом, скрипт Яндекса грузится только на подходе к подвалу;
- **ключа нет или JS API не загрузился** (неверный ключ, домен не в ограничениях ключа, сеть) — бесплатный виджет Яндекс Карт.

Ключ читается в рантайме, поэтому после правки `.env` достаточно рестарта сервиса. Ограничения Яндекса: логотип, копирайты и кнопку «Открыть в Картах» нельзя скрывать и перекрывать; реклама на бесплатном тарифе возможна в обоих вариантах, отключается платным тарифом «Базовый (без рекламы)», 20 000 ₽/год.

## Деплой на VPS в России

Готовый комплект в [deploy/](deploy/README-VPS.md): сборка standalone-артефакта
вне РФ (`deploy/build-artifact.sh`), systemd-юниты сайта и ночного синка
(таймер 00:00 МСК), nginx-конфиг, инструкция. Шрифты самохостятся (fontsource),
сборка не обращается к Google Fonts.

## Структура

```
app/
  page.tsx            # сборка лендинга из секций
  api/lead/route.ts   # приём заявок + Telegram
  privacy/, consent/  # юридические страницы
components/           # секции: Hero, TrustBar, Tasks, DealRoute, Listings, Team, Reviews, Safety, LeadForm, FAQ...
  lead/               # контекст модалки заявки + отправка
data/                 # listings.json, agency.json (сид закоммичен, обновляется npm run sync)
lib/site.ts           # контакты, реквизиты, ссылки на профили
scripts/sync-listings.mjs
research/             # досье на агентство, структура, контент-дайджест, заметки по парсингу
```
