## Что удалось выяснить

### Домклик — парсится обычным fetch (сервер-рендер)
1. HTML страницы агентства содержит `window.__REACT_QUERY_STATE__=` с полным JSON:
   - агентство: name, INN, logoUrl, stats.dealsCount=20, offersCount, rating.avg=5, регион
   - агенты (7): имя, casId, verified, avatarUrl (img.dmclk.ru), stats.dealsCount, rating
   - отзывы (7): текст, рейтинг, дата, dealIssuedAt, ФИО агента, имя автора
   - парсинг: `raw_decode` после `window.__REACT_QUERY_STATE__=` (после JSON идёт ещё код)
2. Открытый API объявлений (без авторизации, limit ≤ 9):
   `https://api.domclick.ru/pts/agencies/v1/offers?company_id=269616&deal_type=sale&limit=9`
   → { id, price, poster_path, address_full, deal_type, link }
   deal_type: sale | rent (запрашивать оба)
3. Картинки: `https://img.dmclk.ru/s1200x800q80{poster_path}` (размерный префикс sWxHqQ), аватары `s200x200q80` — качаются curl'ом без referer.

### ЦИАН — блокирует curl (21KB заглушка), но открывается в реальном браузере без капчи
- Страница компании содержит все карточки объявлений: ссылки `/sale/...`, `/rent/...`, полный текст карточки (цена, адрес, метро, площадь, этаж, описание) и фото `images.cdn-cian.ru/images/{slug}-{photoId}-2.jpg`
- Фото качаются curl'ом напрямую (referer не проверяется); `-1.jpg` = крупнее (720x960+), `-2.jpg` = превью
- Для синка нужен headless-браузер (playwright-core + системный Chrome)

## Архитектура синка
- `scripts/sync-listings.mjs`:
  1. Домклик: fetch страницы агентства → REACT_QUERY_STATE (статистика, агенты, отзывы) + API offers (sale+rent) → data/agency.json
  2. ЦИАН: playwright-core (channel: chrome) → страница company/211681 → карточки → data/listings.json
  3. Скачивание фото в public/listings/{id}/*.jpg и аватаров в public/team/
  4. При недоступности источника — сохраняется предыдущий JSON (комитится в репо как seed)
- Лендинг читает JSON статически (SSG), «источник правды» в data/
