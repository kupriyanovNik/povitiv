# Адаптация под Россию: фактчек и план (август 2026)

Сводка исследования (4 параллельных фактчекера, источники 2025-2026 в каждом пункте; полный дамп с URL — в истории сессии).

## 1. Vercel: для РФ непригоден, даже для демо

- РКН вносил отдельные *.vercel.app и IP Vercel в реестр (например psbs.vercel.app, 01.12.2023, вместе с общими IP 76.76.21.164/9). Ещё в 2021 из-за этого падал nextjs.org.
- 2025-2026: кастомные домены на IP Vercel не открываются у Ростелекома/МТС/мобильных операторов (официальный форум Vercel: кейсы 10.2025-05.2026 без решения); *.vercel.app работает через раз. Сообщество на 02.2026: «Vercel частично заблокирован, Netlify полностью».
- Сам Vercel Россию не блокировал (не работает только оплата российскими картами) — проблема на стороне ТСПУ.
- Cloudflare как прокси тоже нельзя: с 09.06.2025 российские провайдеры режут соединения к Cloudflare-сайтам до ~16 КБ.
- Вывод: прод и демо — только на VPS в РФ (demo.positiv-vt.ru или российский PaaS). povitiv.vercel.app у клиента с мобильного может просто не открыться.

## 2. Telegram: главный удар по нашей архитектуре

- Хронология: 08.2025 — РКН ограничил только звонки (боты работали); 10.2025 — региональные блокировки на юге; 10.02.2026 — официальное замедление по всей стране; 14-17.03.2026 — фактическая блокировка (80-95% сбоев). 11.04.2026 Telegram выкатил маскировку трафика, идут «качели» (массовые сбои 1-3.08.2026).
- **api.telegram.org с российских VPS с ~19.03.2026 недоступен**: ТСПУ/DPI дропает TCP к подсетям Telegram на исходящем трафике (Selectel, Reg.ru и др.). Прямой sendMessage с сервера в РФ — таймауты/504.
- Self-hosted telegram-bot-api ВНУТРИ РФ не спасает: DPI режет сам MTProto.
- Рабочий обход: **релей на зарубежном VPS** (Caddy/nginx reverse-proxy на api.telegram.org, доступ только с IP сайта; бот ходит на relay-URL). Данные при этом остаются на сервере в РФ.
- Клиент Telegram у сотрудников тоже нестабилен без VPN — получатель может не увидеть уведомление.
- Тренд: курс на полную блокировку + принудительная миграция на MAX (предустановка обязательна с 01.09.2025). На горизонте 1-2 лет Telegram-канал уведомлений ненадёжен.

## 3. 152-ФЗ: что требует закон от нашей формы

- Имя+телефон из формы = обработка ПДн, даже без сохранения в базу. Владелец сайта — оператор ПДн.
- **Уведомление РКН об обработке ПДн обязательно** (pd.rkn.gov.ru, через Госуслуги, бесплатно). С 30.05.2025 неподача = штраф 100-300 тыс. ₽ для юрлиц (420-ФЗ от 30.11.2024).
- **Локализация**: с 01.07.2025 (23-ФЗ) сбор ПДн через иностранные БД прямо запрещён — заявка должна СНАЧАЛА записываться в базу на территории РФ. Схема «форма → сразу в Telegram, ничего не храним» стала юридически рискованной. Штрафы до 6 млн ₽.
- **Трансграничная передача**: пересылка заявок в Telegram (юрисдикция ОАЭ, страна НЕ из перечня «адекватных» по приказу РКН № 128) по консенсусу юристов = ТГП → отдельное уведомление РКН и ожидание решения (10 раб. дней) ДО начала. Штрафы с 30.05.2025: юрлица 1-6 млн ₽. На практике малый бизнес массово шлёт лиды в TG без уведомлений, целевых штрафов пока не видно — но клиенту нужно дать честный выбор.
- **Согласие**: текста «нажимая кнопку, вы соглашаетесь» недостаточно по практике РКН — нужен отдельный НЕотмеченный чекбокс + лог факта согласия (дата/время/IP). С 01.09.2025 (156-ФЗ) согласие оформляется отдельным документом.
- Куки-баннер не нужен, пока нет аналитики (у нас куки отсутствуют) — достаточно описания в политике. Если добавят Яндекс.Метрику — нужен баннер с блокировкой скрипта до согласия.
- Запрет иностранных мессенджеров (41-ФЗ, с 01.06.2025) на малое агентство НЕ распространяется (только госорганы, банки, крупные платформы).

## 4. Хостинг-практика РФ

- VPS только у провайдера из реестра РКН (406-ФЗ, с 01.02.2024): Timeweb, Beget, Selectel, Reg.ru — все в реестре. 2 vCPU / 2 ГБ ≈ 550-1000 ₽/мес (цены после повышений 12.2025-01.2026).
- Let's Encrypt для .ru пока работает (несанкционным компаниям выдаёт; LE-SA v1.7 от 04.06.2026 добавил санкционные оговорки — риск есть). GlobalSign 13.06.2026 отозвал сертификаты у ~15-20 тыс. российских доменов. План Б: HARICA. Сертификат Минцифры браузерами не доверяется.
- GitHub из РФ деградирован с 05.2026 (16% обрывов, DPI). npm-зеркала: mirror.yandex.ru, Verdaccio. Google Fonts формально доступен, но при сборке на РФ-VPS рискован.
- → Правильная практика: **собирать артефакт вне РФ** (CI / локально) и деплоить готовый бандл; **шрифты самохостить** (woff2 в репо, next/font/local).
- Парсинг cian.ru с датацентровых IP РФ: антибот фильтрует по репутации IP, датацентровые подсети под подозрением. Наш фолбэк «оставить прежние данные» защищает; опция — резидентный прокси.

## План адаптации (бэклог)

1. **Лид-пайплайн v2** (закрывает и надёжность, и 152-ФЗ):
   - заявка сначала пишется в локальный журнал на VPS (JSONL/SQLite: данные + дата/время/IP/факт согласия) — локализация ч. 5 ст. 18 + доказательство согласия;
   - уведомления фан-аутом с ретраями: email через российский SMTP (первичный канал), Telegram через relay (вторичный, best-effort);
   - env: TELEGRAM_API_BASE (relay-URL), SMTP_*, LEADS_DIR.
2. **Чекбокс согласия** в обеих формах (неотмеченный) + передача consent/IP/времени в API и в журнал.
3. **Самохост шрифтов**: Golos + Geologica woff2 в репо, next/font/local.
4. **Деплой-кит для РФ-VPS**: сборка артефакта вне РФ, systemd/nginx/certbot или Docker-образ; cron синка на VPS; Caddyfile для релея на зарубежном микро-VPS.
5. **Демо** перенести с vercel.app на РФ-площадку перед показами клиентам.
6. **Клиенту на подпись/действие**: уведомление РКН об обработке ПДн (обязательно); решение по каналу уведомлений (email-only чисто юридически; Telegram через релей = подать уведомление о ТГП или принять риск; MAX-бот как опция на будущее); обновлённые политика и согласие.

Примечание: адверсариальная сверка утверждений выполнена частично (лимиты сессии); каждое ключевое утверждение опирается на 3-6 независимых источников с датами.
